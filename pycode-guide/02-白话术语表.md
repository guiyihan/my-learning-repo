## A. 对话与循环

### Agent（智能体）

- **一句话**：能调用工具、多轮完成任务的 AI 程序，不只是聊天。  
- **为什么需要**：编程任务要读文件、跑命令，单轮问答不够。  
- **OpenCode**：选中的角色如 `build`、`plan`。

### Agent Loop（智能体循环）

- **一句话**：模型思考 → 调用工具 → 拿结果 → 再思考……直到结束。  
- **为什么需要**：复杂任务不可能一轮说完。  
- **详见**：[03-Agent循环](./03-Agent循环-一次对话如何跑完.md)

### Session（会话）

- **一句话**：一次编程任务的「笔记本」：消息、工具结果、状态都记在里面。  
- **为什么需要**：要能刷新页面、重启进程后还能接着看。  
- **类比**：Word 文档，不是黑板上的临时粉笔字。

### Provider Turn（一次模型调用）

- **一句话**：向大模型云服务发出去的 **一整次** 请求（含流式返回）。  
- **为什么需要强调「一次」**：OpenCode 规定每轮循环只正式请求模型一次，工具跑完再请求下一次——方便记账、取消、重放。  
- **错误做法**：在内存里偷偷套很多层工具循环却不算「新的一轮」。

### Tool（工具）

- **一句话**：模型可以请求系统执行的动作，如读文件、写文件、跑 bash。  
- **为什么需要**：模型自己不能直接碰你的磁盘，必须通过受控接口。

### `max_steps` / Agent Steps（最大步数）

- **一句话**：限制一个 Agent 最多能进行多少轮「模型决定下一步」的保险丝；到上限后不再让它无限调用工具。  
- **为什么需要**：模型可能一直觉得「还差一步」，不设上限就会持续花 token、跑命令。它限制的是执行步数，不是聊天消息条数。  
- **OpenCode**：新配置常写作 `steps`；`maxSteps` / `max_steps` 是旧名称或其他系统里的常见写法。详见 [03-Agent循环](./03-Agent循环-一次对话如何跑完.md)。

### `doom_loop`（原地打转保护）

- **一句话**：发现模型连续多次用 **相同参数调用相同工具** 时，先停下来问人还要不要继续。  
- **为什么需要**：防止 Agent 卡在「读同一文件 → 再读一次」的死循环里，白烧 token 或重复破坏文件。  
- **OpenCode**：Legacy 执行路径会触发 `permission.ask("doom_loop")`；不同执行路径的保护深度可能不同。详见 [06-权限与命令安全](./06-权限-人机确认与命令安全.md)。

## B. 「先记账，再干活」（最容易晕的一块）

### Admit（准入 / 入队）

- **一句话**：先把用户这句话 **可靠地写进数据库排队**，此时模型可能还没开始跑。  
- **类比**：餐厅先给你发号，厨房还没炒菜。  
- **为什么需要**：网络重试、页面刷新时，不要丢用户已经说出口的话。

### Promote（提升 / 入席）

- **一句话**：到了合适时机，把排队中的用户话 **正式写入可见对话历史**，模型这才能「看见」。  
- **类比**：叫到号，把你领到座位上，厨师开始按你的菜单做。

### Inbox（收件箱 / 待处理输入）

- **一句话**：已经 admit、但还没 promote 的用户输入存放处。  
- **为什么需要**：支持「当前还在跑，新指令先排着」或「立刻转向」。

### Steer（转向）

- **一句话**：默认模式——你中途说「别用 Redis，改用内存」，会在下一轮模型调用前插进去，尽快改变方向。  
- **类比**：菜还在炒，你说少放辣，服务员马上转告后厨。

### Queue（排队）

- **一句话**：明确说「先等当前这波工具跑完，再处理我这句」。  
- **类比**：这桌菜上完再点下一道，避免乱序。

### Drain（抽干 / 跑一轮执行）

- **一句话**：进程里针对某个会话：**把该处理的输入处理掉、该调用的模型调用完**，直到暂时没事可做。  
- **注意**：Drain **不是** 永久保存在数据库里的「任务 ID」；更像「这会儿厨房正在忙这桌」。重启后「正在忙」的状态会丢，但笔记本（会话内容）还在。

### Wake（唤醒）

- **一句话**：告诉执行器「这个会话有新活了，有空就去 drain」。  
- **和 Resume 的区别**：Wake 偏「有新消息再跑」；Resume 偏「强制再跑一下」（例如从中断后继续）。

### Safe Boundary（安全边界）

- **一句话**：当前动作已经收尾、可以安全插入新消息或改变下一步计划的时刻，通常在一次模型调用或工具执行结束之后。  
- **为什么需要**：用户中途发来「别改数据库」时，不能把它硬塞进正在生成到一半的模型响应里；等到边界再处理，历史才不会前后矛盾。  
- **OpenCode**：Steer 输入会在下一次合适的 provider-turn 边界被 promote。详见 [03-Agent循环](./03-Agent循环-一次对话如何跑完.md)。

### SessionRunCoordinator（会话运行协调器）

- **一句话**：同一个 Session 同一时刻只让一条本地执行链真正干活；重复唤醒会合并或加入当前执行，不同 Session 仍可并行。  
- **为什么需要**：否则用户连点两次继续，可能出现两个循环同时写一份对话，消息和工具结果互相穿插。  
- **OpenCode**：它是 **进程内、按 Session ID** 的协调器，不是数据库里的永久 `run_id`，也不是跨机器调度器。详见 [09-取消、恢复与容错](./09-取消-恢复与容错.md)。

## C. 提示词与模式

### System Context（系统上下文）

- **一句话**：告诉模型「你现在在哪个目录、今天几号、有哪些技能可用」等 **环境事实**。  
- **不要叫成笼统的 system prompt**：人格说明书（「你是编程助手」）和环境事实（「当前仓库路径」）最好分开。  
- **详见**：[04-提示词与工作模式](./04-提示词与工作模式.md)

### Context Epoch（上下文世代）

- **一句话**：某一版「完整环境说明」生效的时间段；中间环境变了，用「更新说明」追加，而不是每次把整本说明书撕掉重印（利于缓存、也利于回放）。  
- **类比**：员工手册大修订算新版本；平时只发变更通知。

### Mid-Conversation System Message（对话中途的系统消息）

- **一句话**：会话开始以后，由系统插入的一条高优先级更新，例如「工作目录已变化」或「现在切到只读模式」。  
- **为什么需要**：长任务进行中环境会变；如果仍让模型按开场时的旧事实行动，就可能找错目录或违反新限制。  
- **OpenCode / pycode**：适合承载 Context Epoch 之间的增量更新，但必须明确哪些模型 Provider 支持这种消息位置。详见 [04-提示词与工作模式](./04-提示词与工作模式.md)。

### Build 模式 / Plan 模式

- **Build**：可以改代码、跑命令（干活）。  
- **Plan**：默认只读分析，把计划写到计划文件里，你点头后再干。  
- **关键**：Plan 不只靠「请模型别改文件」，还有 **权限硬限制**。

### Intent Recognition（意图识别）

- **一句话**：自动判断「用户是想规划还是想执行」。  
- **OpenCode 现状**：**没有**单独的意图分类器；模式靠你（或 UI）显式选择 Agent。  
- **若 pycode 要自动切换**：那是你自己的新功能。

## D. 工具生态

### MCP（Model Context Protocol）

- **一句话**：一种「外挂工具箱」的标准插头。别人写好 MCP 服务器（比如连公司文档、浏览器），Agent 就能调用。  
- **类比**：USB 接口——键盘、鼠标都能插。

### ACP（Agent Client Protocol）

- **一句话**：让编辑器或其他客户端用统一方式连接 Coding Agent 的协议。  
- **为什么需要**：客户端不必为每一种 Agent 单独发明消息、工具进度和权限确认格式。  
- **详见**：[22-外部协议 ACP 与 A2A](./22-外部协议ACP与A2A.md)。不要和 MCP 混淆：MCP 主要是 **Agent 接工具**，ACP 主要是 **客户端接 Agent**。

### A2A（Agent-to-Agent）

- **一句话**：让两个独立 Agent 服务通过协议互相交任务、回传状态与结果。  
- **为什么需要**：跨进程、跨机器或跨产品协作时，不能只靠本进程里的 `task` 子会话。  
- **详见**：[22-外部协议 ACP 与 A2A](./22-外部协议ACP与A2A.md)。在入门阶段先记一句即可：A2A 是外部 Agent 互联，不等同于 OpenCode 内部 Subagent。

### Skill（技能）

- **一句话**：一篇「怎么做某类事」的说明书（通常是 `SKILL.md`）。  
- **怎么用**：系统提示里只列技能名称和简介；模型觉得需要时，用 `skill` 工具把 **全文加载进来**。  
- **不是**：加载 Skill 不会自动长出一堆新按钮式工具（除非说明书里教它去调已有工具）。

### Hook（钩子）

- **一句话**：在关键时刻插入自定义逻辑，例如「工具执行前改参数」「执行后改写输出」。  
- **用途**：插件、审计、公司内部规范。

### Plugin（插件）

- **一句话**：一包可安装、可配置的扩展代码，可以注册工具、Hook、鉴权方式或其他集成。  
- **为什么需要**：公司能力和第三方服务不应该都硬塞进 Agent 核心；插件让扩展独立发布和启停。  
- **OpenCode**：Plugin 是扩展的 **代码载体**，Hook 是它可以使用的 **插入点**，Skill 则主要是给模型看的 **操作说明书**。详见 [13-Hooks 与插件扩展](./13-Hooks与插件扩展.md)。

### `toModelOutput` / Truncate（模型输出转换 / 截断）

- **一句话**：`toModelOutput` 把工具的领域结果变成适合喂给模型的内容；Truncate 再把过长内容缩短，并保留查看完整结果的线索。  
- **为什么需要**：UI 想展示完整日志，模型却不该被几十万行输出塞满；「保存什么、展示什么、喂模型什么」必须分开。  
- **OpenCode**：新工具边界显式提供 `toModelOutput`；截断后通常给预览和落盘路径。详见 [14-结构化工具结果与输出边界](./14-结构化工具结果与输出边界.md)。

## E. 安全与人机交互

### HITL（Human-in-the-Loop，人在回路）

- **一句话**：关键步骤必须人点头才能继续。  
- **两类常见**：  
  - **权限确认**：能不能跑这条危险命令？  
  - **澄清提问**：需求不清楚时，用问卷问你。

### Permission（权限）

- **一句话**：规则表：某个动作对某个目标是 `allow`（允许）/ `deny`（拒绝）/ `ask`（问人）。  
- **例子**：`bash` 里 `rm *` → deny；读 `.env` → ask。

### BashArity（Bash 命令前缀长度）

- **一句话**：按命令家族决定「记住前几段」作为授权模式，例如区分 `git status` 和 `git push`。  
- **为什么需要**：用户点「always」时，记整条命令会窄得没用，只记 `git` 又宽得危险；BashArity 在两者之间取合适前缀。  
- **OpenCode**：主要用于 Legacy Bash 权限归一化，V2 路径仍可能只按整条命令判断。详见 [06-权限与命令安全](./06-权限-人机确认与命令安全.md)。

### `external_directory`（项目外目录权限）

- **一句话**：当工具想访问当前工作区以外的路径时，触发一类单独的权限判断。  
- **为什么需要**：允许 Agent 改当前项目，不代表也允许它读取 `~/.ssh` 或删除你的个人文档。  
- **OpenCode**：它是权限动作，不是 Docker 沙箱；对命令参数中路径的识别深度会随执行路径而异。详见 [17-工作区沙箱与命令安全深度](./17-工作区沙箱与命令安全深度.md)。

### CorrectedError / RejectedError / DeniedError

- **一句话**：三者都表示工具没有获准，但原因不同：`CorrectedError` 是人拒绝并给了修改意见，`RejectedError` 是人直接拒绝这一次，`DeniedError` 是预设规则直接挡住。  
- **为什么需要**：拒绝并不总等于结束；有纠正意见时模型可以换方案，用户明确拒绝时通常应停止继续越界，规则拒绝则要告诉模型这条路不可走。  
- **OpenCode**：这组名称主要出现在 Legacy Permission；V2 的错误拆分略有不同，不要只按类名机械映射。详见 [06-权限与命令安全](./06-权限-人机确认与命令安全.md)。

### Sandbox（沙箱）——容易误会

- **人们以为**：每个命令都在 Docker 里跑，删不坏真电脑。  
- **OpenCode 默认更接近**：在你的真实用户权限下跑；靠权限弹窗 + 工作目录限制。  
- **文档里的 containers**：多是 CI 构建镜像，不是 Agent 运行时监狱。  
- **worktree**：用 git 工作树隔离一份代码目录，也不是完整 OS 沙箱。

## F. 记忆与压缩

### Session History（会话历史）

- **一句话**：准备喂给模型的那段对话内容（可能已经压缩过）。  
- **注意**：数据库里可能仍保存压缩前的全文，方便你回看；模型未必每次都看见全文。

### Compaction（压缩 / 摘要检查点）

- **一句话**：对话太长时，把旧内容收成结构化摘要 + 保留最近原文，腾出上下文窗口。  
- **关键**：**不是删除用户数据**，是改「模型看见的那一版」。

### `prune`（裁掉旧工具输出）

- **一句话**：把较早、较大的工具输出从「继续喂给模型的内容」里拿掉，通常不需要重新总结整段对话。  
- **为什么需要**：测试日志、搜索结果最占上下文，但旧结果往往不值得永远原样携带；先 prune 可以延后更昂贵的 compaction。  
- **OpenCode**：`prune` 主要是 **Legacy Session compaction** 的一部分；它偏向清理旧 tool output，compaction 则会生成对话摘要。两者都不应被理解成随意删除完整审计记录。详见 [08-会话记忆与上下文压缩](./08-会话记忆与上下文压缩.md)。

### Short-term / Long-term Memory（短时 / 长时记忆）

- **OpenCode 语境**：  
  - 短时 ≈ 当前喂给模型的窗口  
  - 长时 ≈ 数据库里完整事件/消息  
- **不是**：默认没有「向量数据库跨项目回忆」那种长期语义记忆；那要另做。

## G. 多 Agent

### Subagent（子智能体）

- **一句话**：主会话通过 `task` 工具开一个 **新的子会话**，让专门的角色（如只读探索）去干一摊活，再把结果摘要回来。  
- **不是**：在同一段对话里假装换了一个人设那么简单——通常是真的另一本笔记本。

### task_id

- **一句话**：子任务会话的 ID。再次传入同一个 ID = **接着上次那个子会话继续**，而不是新开一本。

## H. 工程词（读架构章会遇到）

### Schema / Protocol / Core / Server / Client

- **Schema**：数据结构合同（消息长什么样）  
- **Protocol**：HTTP 接口合同  
- **Core**：真正干活的领域逻辑  
- **Server**：把 Core 挂到 HTTP 上  
- **Client**：给 UI / SDK 用的调用库（不应直接碰数据库）

### Event Sourcing（事件溯源）粗解

- **一句话**：先记下「发生了什么事」（事件），再投影出「现在对话长什么样」。  
- **好处**：可重放、可同步到 UI、断线用序号接着收。

### Durable vs Live

- **Durable（耐久）**：写入数据库、断线可重放的事件（如「工具已完成」）。  
- **Live（直播）**：打字机式的增量（如「又吐出三个字」），断了就丢，刷新后靠耐久状态补齐。

### Location / Placement（位置 / 放置）

- **一句话**：Location 描述 Session 的工作环境与资源所在位置；Placement 是决定「这次执行应该放到哪个 Location / 进程」的过程。  
- **为什么需要**：本机项目、远程工作区和未来的集群节点不能共用一套隐含的当前目录；执行必须找到正确的文件系统、工具和权限环境。  
- **OpenCode**：V2 的模型是 Session 记录 Location，执行开始时再发现放置位置；当前本地实现仍以进程内执行为主。详见 [21-运行形态与部署](./21-运行形态与部署.md)。

### Embedded mode（嵌入式模式）

- **一句话**：宿主程序把 OpenCode 核心和 Client 直接装在同一进程里使用，而不是先启动一个独立 HTTP 服务再通过网络访问。  
- **为什么需要**：SDK、测试或桌面应用可少管理一个外部进程，同时仍复用 Client / Route 契约。  
- **OpenCode**：`sdk-next` 会创建内嵌 routes，并用进程内 `fetch` 连接 Client；「内嵌」不等于绕过权限或把所有状态变成全局变量。详见 [21-运行形态与部署](./21-运行形态与部署.md)。

## I. 历史操作：回退、快照与分叉

### Revert / Snapshot / Fork（回退 / 快照 / 分叉）

- **一句话**：Snapshot 是某时刻文件状态的记录；Revert 是借助记录把现有工作区退回旧状态；Fork 是从某个历史点另开一条新会话分支，原分支仍保留。  
- **为什么需要**：三者回答不同问题——Snapshot 回答「当时文件什么样」，Revert 回答「怎样撤销后来改动」，Fork 回答「怎样从旧节点尝试另一种方案」。  
- **OpenCode**：不要把「Fork 会话」误当成自动创建 Git branch，也不要把 Revert 误当成删除聊天记录。详见 [15-Fork、Revert 与文件快照](./15-Fork-Revert与文件快照.md)。

## 快速自测

用自己的话解释下面问题（不会就回正文）：

1. Admit 和 Promote 差在哪？
