# PyCode 设计指南：阅读说明

> 这套文档面向 **刚刚开始学 Agent 开发的读者**，也服务 **要评审 OpenCode 设计、规划 pycode 的工程师**。  
> 目标：读完后，你能理解 OpenCode「为什么这样设计」，并据此规划自己的 Python 项目（pycode）。  
> 你 **不需要** 先读过 OpenCode 源码。

**对齐基线**：仓库默认分支 `dev`；设计以 **V2 Session Core** 为准，V1 Legacy 仅作对照。权威规范见仓库根目录 `CONTEXT.md`、`specs/v2/session.md`、`AGENTS.md`。

---

## 这套文档在讲什么？

OpenCode 是一个开源的 AI 编程助手（Coding Agent）。  
它不只是「把用户问题发给大模型」，而是一整套工程：

- 怎么循环调用模型、怎么用工具改代码
- 怎么问人确认危险操作、怎么澄清需求
- 怎么记上下文、怎么压缩太长的对话
- 怎么取消、怎么恢复、怎么开多个子 Agent
- 怎么扩展 MCP / Skill / Hook、怎么做可观测性

我们研究它的设计，是为了用 Python **复刻同一套思路**（叫 pycode），而不是照搬 TypeScript 语法。

## 每章统一结构

主题章尽量都按这个节奏写（方便对照学习）：

1. **这一章要解决什么问题**（用日常例子）
2. **如果做成最 naive 的版本会怎样**（常见新手坑）
3. **OpenCode 选择了什么设计**（V2 为主；V1 用对照框）
4. **为什么这样演进**（设计动机）
5. **配置 / 接口长什么样**（尽量给可抄的例子）
6. **走一遍完整示例**（含 mermaid）
7. **优点 / 缺点 / 你做 pycode 时要注意什么**
8. **对应源码位置**（路径级；初学可跳过）

**例外**（不必硬套 8 段）：

- **02 术语表**：词典体
- **00 / 12**：导航与清单体
- **21 / 22**：偏产品外延，可短于核心章

## V1 / V2 总对照表

| 主题 | V2（pycode 对齐目标） | V1 Legacy（产品仍可能走这里） |
|------|----------------------|-------------------------------|
| 用户输入 | admit → inbox → promote；steer/queue | 直接写消息再 `SessionPrompt.loop` |
| 模型调用 | 每 Provider Turn **一次** `llm.stream` | `SessionProcessor` 内流式处理 |
| 工具 | `ToolRegistry.materialize` + `settle` | `SessionTools.resolve` + processor |
| Plan/Build 提醒 | parity 表多为 missing/partial | `reminders.ts` + `plan-mode.txt` |
| `task` 子 Agent | Core 侧多为 TODO/未迁全 | `tool/task.ts` 成熟 |
| Shell 深度安全 | 简化整句 ask（TODO 移植） | tree-sitter AST + BashArity |
| Plugin hooks | 目标形状更清晰，迁移中 | `tool.execute.before/after` 已接线 |
| Fork | 非 V2 drain 身份 | `session.fork` 成熟 |
| 崩溃续跑 provider | **刻意 deferred** | 同进程 cleanup + 不自动猜 |

每章会用 **「V2 已有 / Legacy only / deferred」** 小标签标清现状，避免你照着半成品路径复刻。

## 诚实边界（评审时先记住）

1. **没有独立意图识别（NLU）**：模式靠显式选 Agent + 权限 + `question` 工具。  
2. **默认没有 OS 沙箱**：命令跑在宿主机用户权限下；安全靠 Permission + HITL。  
3. **部分 Hook 仅有类型未接线**（例如 `permission.ask`）：见 [13](./13-Hooks与插件扩展.md)。  
4. **崩溃后自动重试模型调用** 尚未做成产品能力：见 [09](./09-取消-恢复与容错.md)。
